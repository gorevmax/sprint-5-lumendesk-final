# Результаты проверки RAG-помощника LumenDesk: 12 контрольных вопросов

Дата прогона: 2026-11-18. Среда: Windows 11 x64, Python 3.13.16, CPU. Индекс `idx-20261118T202118Z-d51167`: 42 документа, 692 фрагмента, коллекция `lumendesk-support`, E5, cosine.

## Как проводилась проверка

1. **Ожидания до запуска** записаны в [eval/expectations.md](eval/expectations.md) по чтению оригиналов. В Python и в поиск они не передаются.
2. **Раунд A** (политика v2). Для каждого вопроса выполнен новый запуск: отдельный процесс `ask`, затем чтение JSON поиска, затем raw-ответ по найденным фрагментам, затем `finalize`. Добавлен вопрос вне базы (x01).
3. **Сверка с оригиналами** — по файлам из `documents/`, прочитанным напрямую:
   - PDF и DOCX — через `scripts/extract.py`;
   - XLSX — по ячейкам, через `check_extraction.raw_sheet_cells`;
   - MD, TXT, CSV — построчно.

   Для каждой цитаты из EN/FR-источника русский текст сопоставлен с отрывком оригинала из citation-map: числа сравнены автоматически, условия и отрицания — вручную.
4. **Ошибки.** Найдены, причины проверены диагностикой, правка внесена в виде политики **v3**. Политика v2 и её результаты сохранены без изменений.
5. **Раунд B** (политика v3). Все 12 вопросов и x01 выполнены заново, потому что правка меняет поиск для всех вопросов. Затем повторены отрицательные проверки и итоговые проверки корпуса.

**Оценки по четырём направлениям:**
- **Поиск** — найдены ли подходящие разрешённые фрагменты;
- **Ответ** — следует ли ответ из найденных сведений и выбрано ли правильное действие;
- **Перевод/цитаты** — верны ли перевод, цитаты и места в оригиналах;
- **Доступ/правила** — соблюдены ли ограничения доступа и правила поведения.

Обозначения: ✅ верно, ⚠️ верно, но неполно, ❌ ошибка.

Пути к файлам истории (все в `evidence/`):
- `retrieval-{run}.json` — результат поиска;
- `retrieval-trace-{query_id}.json` — все кандидаты, включая отсечённые порогом;
- `answer-{run}.raw.json` — ответ ИИ;
- `result-`, `trace-`, `citation-map-{capture_id}.json` — результат `finalize`;
- общий журнал — `history.jsonl`.

## Ошибки, причины и правки

### E1. Вопрос вне базы получал `forbidden` (правила поведения) — исправлено

- **Наблюдение (A).** Вопрос «Какая погода будет завтра в Париже?» получил `context_state = forbidden`. По правилу v2 ответ звучал как «сведения есть только в закрытых материалах, обратитесь к руководителю». Это неверное действие, и оно намекает на содержимое закрытых документов.
- **Причина.** Порог `authorization_probe_distance = 0.35` слишком широк для распределения расстояний E5: ближе 0,35 оказывается любой закрытый фрагмент. Диагностика без генерации ответа:
  - погода — лучший разрешённый 0,230, лучший закрытый 0,270;
  - борщ — 0,240 и 0,252;
  - Q7 — 0,216 и 0,202.
- **Правка.** В `behavior/v3.json` задано `forbidden_rule = probe_and_closer_than_allowed`: `forbidden` выставляется, только если закрытый фрагмент ближе 0,35 **и** ближе лучшего разрешённого кандидата. Код — `rag_demo/storage.py`, тест — `test_v3_forbidden_only_when_restricted_is_closer`.
- **До → после.**
  - x01: `forbidden` → `empty`, ответ «в базе нет сведений» (cap-20261118T210005Z-cd5ac6 → cap-20261118T211103Z-7371b7).
  - Q7: `forbidden` → `forbidden`, без изменений.

### E2. В Q12 не найдена длительность окна сертификатов (поиск) — исправлено

- **Наблюдение (A).** 8 найденных фрагментов: 6 из runbook «SAML incident handling.docx» и 2 из личных заметок. Строка реестра `параметры-входа.csv`, строка 2 («Старый и ожидающий сертификаты принимаются одновременно 7 календарных дней») прошла порог (0,172), но оказалась только на 18-м месте. Ответ A честно сообщил, что длительности в найденных фрагментах нет, и числа не выдумал. Но ответ неполный.
- **Причина.** Вопрос составной («сколько» + «когда нужен руководитель»). Фрагменты runbook закрывают обе части и вытесняют строку реестра, которая закрывает одну. Расстояния у кандидатов плотные (0,13–0,18).
- **Проверенные варианты (диагностика, без ответов):**
  - top_k = 16: строка 2 остаётся 18-й;
  - ограничение текстовых фрагментов одного документа (3–4): нужная строка не появляется, а цитаты Q9, Q11, Q12 теряются;
  - переранжирование RRF с BM25: Q12 исправляется, но теряются цитаты Q9, Q10 и Q12.
- **Правка (v3).** Векторные top_k = 8 сохраняются без изменений. Из кандидатов, прошедших порог 0,20 (пул 40), добавляются до 2 фрагментов с наибольшим совпадением слов вопроса (BM25, усечение слов до 6 символов). Параметры `lexical_extra = 2`, `lexical_pool = 40`, `lexical_stem = 6`. Добавленные фрагменты перечислены в `filtering.lexical_added`. Тест — `test_v3_lexical_extra_keeps_dense_top_k`. Правка не трогает индекс, поэтому переиндексация не нужна.
- **До → после.**
  - Q12: строки 2 и 12 из `параметры-входа.csv` вошли в выдачу (ранги 9–10). Ответ B: «7 календарных дней» + случаи для руководителя (cap-20261118T205958Z-cd6d4d → cap-20261118T211056Z-88973e).
  - Во всех 12 вопросах первые 8 фрагментов не изменились, ни одна цитата раунда A не потеряна.
  - В Q8 добавилась строка Starter (25 MiB), и уточняющий ответ стал полнее.
  - В Q6 добавилось «Компенсация требует отдельной проверки условий и не обещается в статусном сообщении».
  - В остальных вопросах добавленные фрагменты на ответ не влияют.

### E3. В Q9 и Q4 не найдены фрагменты, нужные для полноты (поиск) — не исправлено, ограничение

- **Q9.** Раздел «Обязательные поля» в «Customer handover.docx» (`onboarding-handover::chunk-02`, абзацы 5–10) — на 33-м месте (0,177). Из-за этого в ответе нет пунктов «ответственный за онбординг» и «окно миграции с часовым поясом». Остальные пункты верны и подтверждены цитатами.
- **Q4.** Строка 8 `webhooks-reprises.csv` («после шестой неудачной попытки событие переходит в dead_letter») — на 35-м месте. Ответ верен, но не объясняет, что такое dead_letter.
- **Причина.** Короткий список или строка таблицы мало пересекается с формулировкой вопроса и по смыслу, и по словам. Ни один проверенный вариант (top_k = 16, ограничение на документ, BM25) не поднимает эти фрагменты.
- **Почему не исправлено.** Подгонять перевод («онбординг» → «первоначальное подключение») или разбиение под формулировку контрольного вопроса было бы необоснованно. Следующий шаг — расширение по структуре документа: добавлять соседние разделы того же документа, если на него приходится больше половины выдачи. Это требует отдельного решения и оценки.

### E4. Ошибки составления ответа в первой сессии — исправлены до этого прогона

- **Q1.** Тезис про одновременную загрузку был без цитаты. Исправлено в `answer-q01-agent-v2.raw.json`, обе проверки остались в `history.jsonl`.
- **Q4.** Французские названия столбцов были вписаны по памяти («Type», «Minutes depuis l'envoi initial»). Перед `finalize` сверено с заголовком CSV и исправлено на «Nature», «Minutes depuis envoi initial».

### Оставшиеся ограничения

1. **Поиск находит не всё (E3).** Короткие списки и отдельные строки таблиц могут не попасть в выдачу, даже если ответ именно в них. Подтверждено дважды: раздел «Обязательные поля» в №9 на 33-м месте, определение dead_letter в №4 на 35-м месте. Пропуск заметен, только если о нём намекает сама выдача: в №9 помощник прямо написал, что перечня нет. В других вопросах такой пропуск может остаться незамеченным. **Ответ «по найденным фрагментам» не равен ответу «по всему документу».**
2. **Порог не откалиброван для руководителя.** При действующей политике v3 руководитель на №7 получает «нет сведений», хотя ответ ему доступен (`retrieval-c-q07-lead.json`). Калибровка предлагает порог 0,214 (`behavior/v4.json`). Но окно узкое (±0,002), и порог подобран на тех же вопросах. Пока v4 не проверена на новых вопросах, «нет сведений» для руководителя не значит, что сведений нет.
3. **Близкие по теме вопросы без данных проходят порог.** У вопроса о выручке (x03) лучший фрагмент на 0,1685, поэтому состояние `available`. Отказ в таком случае обеспечивает только чтение найденных фрагментов по смыслу, порог здесь не помогает.
4. **Два фрагмента, добавленные по совпадению слов, могут меняться от запуска к запуску** (см. наблюдение по №4). Основной ответ от этого пока не менялся, но повторная проверка может дать другую выдачу.
5. **Перевод проверен, но не полностью.**
   - Все 26 EN/FR файлов переведены целиком.
   - Автоматическая сверка (числа, коды, отрицания, условия, роли, длина) пройдена, 33 срабатывания разобраны вручную. При подготовке исправлены 3 настоящие ошибки: пропущенное «deux» в №49, лишнее отрицание в №04, неграмматичная форма в №36 и №49.
   - Перевод выполнен моделью, а не переводчиком. Вручную по смыслу сверено только около 50 переведённых фрагментов, на которые ссылались ответы. Остальные около 700 сверены только автоматически.
   - Спорные, хотя допустимые решения: «sont fermés» переведено как «не проводятся», английское «onboarding» оставлено как «онбординг». Второе, возможно, мешает поиску, когда вопрос сформулирован как «первоначальное подключение» (№9).
6. **У пяти источников не указан владелец:** webhooks-reprises.csv, hosting regions export.csv, хранение - сверка сентября.csv, ответы api новый.csv, notification-events sept.csv. Помощник отвечает по ним и предупреждает об этом (№2, 4), но подтвердить значения не может.
7. **Роль не подтверждает личность.** `--role` — параметр команды, `support_lead` может указать кто угодно.

### Непроверенные ситуации

- **Вопросы на английском или французском** и ответы не на русском.
- **Диалог из нескольких шагов.** Уточнение после `clarify` с новым поиском не проверялось.
- **Вопросы, для ответа на которые нужны и разрешённые, и закрытые документы сразу**, а также вопросы руководителя по другим закрытым документам: «Возвраты оплаты» и «Журнал аудита» не запрашивались.
- **Внедрённая инструкция в найденном тексте.** Два таких фрагмента в «Customer handover.docx» убраны в карантин и в индекс не попали. Как помощник поведёт себя, если подобный текст всё же попадёт в выдачу, не проверялось.
- **Противоречие, которое не отмечено в реестре.** Противоречие в №6 найдено, потому что его выявили при подготовке. Новое неотмеченное противоречие помощник заметит только при чтении фрагментов.
- **Вопросы о старых версиях** («как было в 2025 году») и об исключённых черновиках.
- **Изменение исходников после индексации.** Отказ искать по устаревшему индексу проверен в первой сессии, но только на изменённом подготовленном тексте. Полный путь «изменён исходник → подготовка → перевод → индекс» не повторялся.
- **macOS.** Команды описаны в README, но не запускались.
- **Длинные вопросы.** Лимит в 512 токенов реализован, но вопросов длиннее не было.

### Когда нужен человек

| Ситуация | Почему | Кто |
|---|---|---|
| `escalate`: действующие документы противоречат друг другу (№6, ставка 20 % или 15 %) | по документам правило не выбрать; регламент прямо требует передать вопрос | Finance и Support Operations |
| Компенсации, возвраты, суммы для клиента | компенсацию нельзя обещать в статусном сообщении; решение принимают после проверки условий | Finance, руководитель поддержки |
| `forbidden` (№7) и вопросы о злоупотреблениях, журналах аудита, возвратах | материалы только для руководителя; пока v4 не включена, руководитель тоже может получить «нет сведений» и должен открыть документ сам | руководитель поддержки |
| SAML: 3 неудачных входа за 15 минут, блокировка привилегированной учётной записи; раскрытие API-ключа | документы прямо требуют эскалации руководителю, а при раскрытии ключа — передачи incident ID | руководитель поддержки |
| Ответ с пометкой о неполноте («в найденных фрагментах нет…», №9) или не найден параметр (№12 при v2) | поиск мог пропустить нужный раздел; регламент SAML при ненайденном параметре велит обратиться к Identity Platform | сотрудник открывает указанный документ; Identity Platform |
| Значение из источника без владельца используется в споре с клиентом (№2, 4) | происхождение не подтверждено | владелец данных (API, Workspace Platform) |
| Персональные данные, юридические вопросы, исключения из правил | вне полномочий помощника (spec.md §8) | руководитель поддержки, Privacy Operations |
| Любой ответ, который уходит клиенту | `finalize` подтверждает, откуда взята цитата, но не то, что ответ подходит к конкретному workspace, тарифу и времени | сотрудник, который отправляет ответ |

**Итог.** Помощнику уже можно доверить поиск и объяснение правил по действующим документам. Сотрудник получает ответ с проверяемыми ссылками и отрывками оригинала, а отказы, уточнения и эскалации на всех проверенных вопросах выбраны верно. За человеком остаются окончательный ответ клиенту, противоречия, деньги, доступ и ответы с пометкой о неполноте. Прежде чем доверять помощнику больше, нужно:
- проверить политику v4 на новом наборе вопросов;
- устранить пропуски поиска E3;
- проверить ситуации из списка непроверенных.
