# Спецификация: RAG-помощник поддержки LumenDesk

Основание: [project-task.md](project-task.md), [README.md](README.md).
Статус: v4, 2026-11-18 (реализован пакет `rag_demo`: индекс, поиск с ролью, finalize; см. [README.md](README.md)).

## 1. Назначение

ИИ-помощник для сотрудников поддержки LumenDesk (вымышленная платформа совместной работы). Помощник:

- отвечает на русском языке;
- находит правила продукта в разрешённых действующих документах компании;
- указывает источник каждого факта (файл-оригинал и проверяемое место в нём);
- уточняет недостающие условия (тариф, время, workspace и т. п.) вместо догадок;
- обозначает ситуации, где нужен человек (эскалация).

Разделение ролей в системе:

- **Python** — подготовка корпуса и поиск фрагментов (retrieval).
- **Модель текущего чата ИИ** — формирует ответ только по найденным фрагментам и указывает источники.

## 2. Пользователи и уровни доступа

| Роль | Описание | Доступ к документам |
|---|---|---|
| `support_agent` | Специалист поддержки | Общие материалы поддержки и продукта |
| `support_lead` | Руководитель группы поддержки | Всё, что доступно `support_agent`, плюс материалы для руководителей |

Требования:

- Роль передаётся в поиск как параметр. Фрагменты недоступных документов отсеиваются в Python и не попадают в контекст модели (см. п. 7.6).
- Соответствие документов ролям хранится в файле политики `access.csv`, а не в индексе. Поэтому изменение политики не требует переиндексации.
- Если ответ требует недоступного роли документа, помощник сообщает, что информация недоступна для этой роли, и предлагает обратиться к руководителю. Содержание закрытого документа он не пересказывает.
- Правило назначения ролей по умолчанию: документы из папок `Для руководителей/` доступны только `support_lead`. Остальные правила фиксируются в `inventory.csv` или в отдельном файле доступа (см. п. 9).

## 3. Тематика

Помощник отвечает на вопросы о тарифах, рабочих пространствах, файлах, восстановлении (Корзина), поддержке (SLA, срочность, эскалации), API и настройках доступа (SAML, роли, гости).

На вопросы вне тематики, а также на вопросы, по которым в корпусе нет ответа, помощник прямо говорит, что в базе нет сведений, и ничего не выдумывает.

## 4. Исходные данные

- Расположение: `documents/` (в постановке указано `docs/`, фактическая папка называется `documents/`). Это 50 файлов в подпапках.
- Форматы: `md` (10), `txt` (8), `csv` (8), `xlsx` (8), `docx` (8), `pdf` (8).
- Языки: русский, английский, французский.
- **Исходники не удаляются и не изменяются.** Все производные данные (тексты, переводы, индекс) пишутся в отдельные каталоги.

### 4.1. Метаданные

По постановке у каждого документа есть поля `id`, `title`, `owner`, `version`, `updated`, `permission`, `sensitivity`, `inclusion_status`.

Результат первичного осмотра: в проверенных `md`/`txt` нет блока метаданных в начале файла, а в `docx` поля `title` и `created/modified` есть только в свойствах документа. Поэтому извлечение метаданных выполняется в таком порядке:

1. Блок метаданных в начале файла (front matter, «ключ: значение»), если он есть.
2. Свойства Office-документа (`docProps/core.xml`, `custom.xml`) и PDF (Info/XMP).
3. Служебный лист или служебные строки в таблицах.
4. Если поле не найдено, оно остаётся пустым. Признаки из текста и имени файла («копия», «final», «новый», «черновик», даты, фразы вида «порядок заменён», «архив») используются только как обоснование в `reason`, а не как подставленное значение метаданных.

Документ, у которого нет подтверждённых `permission: allowed`, `sensitivity: synthetic` и `inclusion_status: approved`, получает `exclude` (принцип «по умолчанию закрыто»).

## 5. Инвентаризация корпуса

### 5.1. `inventory.csv`

Одна строка на каждый исходный файл (50 строк плюс заголовок). Кодировка UTF-8, разделитель запятая, кавычки по RFC 4180.

Столбцы: `path,id,title,owner,version,updated,status,reason`

- `path` — относительный путь от корня проекта.
- `id`, `title`, `owner`, `version`, `updated` — значения из документа (см. 4.1).
- `status` — `include` или `exclude`.
- `reason` — краткое основание решения (например, `approved, актуальная версия` / `permission: restricted` / `старая версия; заменён <path>` / `полный дубль <path>; оставлен оригинал в формате docx`).

### 5.2. Правила включения

Документ получает `include`, только если выполнены все условия:

1. `permission: allowed`;
2. `sensitivity: synthetic`;
3. `inclusion_status: approved`;
4. документ актуален: нет более новой версии с тем же `id` или темой (по `version`, а при равенстве по `updated`);
5. документ не является исключённой копией полного дубля.

Обработка дублей и версий:

- **Полный дубль** (совпадает содержимое после нормализации текста, в том числе в разных форматах, например `docx` и `pdf`): включается одна копия, остальные исключаются. В `reason` указываются причина выбора (более полный формат, каноническое расположение, отсутствие пометки «копия») и путь оставленной копии.
- **Старая версия** исключается, если есть новая. В `reason` указывается путь заменяющего документа.
- У включённых документов `id` уникальны. Исключённая копия может иметь тот же `id`.
- Перевод не считается дублем оригинала (см. п. 6).

### 5.3. `corpus-passport.md`

Краткий паспорт базы:

- назначение базы и целевые роли;
- состав включённых файлов (таблица: путь, `id`, `title`, язык, роли доступа), сформированный строго по строкам `include` из `inventory.csv`;
- сводка причин исключений, сгруппированная по видам (доступ, чувствительность, статус, старая версия, дубль), с перечнем файлов;
- дата сборки и версия инвентаря.

## 6. Переводы

- Английские и французские документы, включённые в корпус, переводятся на русский язык.
- Перевод хранится отдельным файлом (например, `corpus/translations/<id>.ru.md`) с заголовком: `source_path`, `source_id`, `source_lang`, дата перевода.
- Структура перевода (разделы, абзацы, строки таблиц) повторяет оригинал, чтобы каждый фрагмент перевода можно было сопоставить с местом в оригинале.
- В индекс попадают и оригинал, и перевод. Ссылка в ответе всегда ведёт на **оригинал** (путь и место). Пометка «перевод» допускается.
- Числа, тарифы, сроки, коды ошибок и названия полей API переносятся без изменений.

## 7. Среда, модель и индекс (Python)

### 7.1. Среда разработки

| Компонент | Значение |
|---|---|
| Язык | Python 3.13 |
| Вычисления | CPU (GPU не требуется) |
| Рабочая среда | VS Code с расширением ИИ (Claude Code), у которого есть доступ к папке проекта и возможность выполнять команды |
| LLM для ответов | модель текущего чата ИИ в этом расширении (Claude). Модель не вызывается из Python: она читает JSON `python -m rag_demo ask` и отвечает по [rag-policy.md](rag-policy.md) |
| Модель эмбеддингов | `intfloat/multilingual-e5-base`, локально через `sentence-transformers` |
| Векторная БД | Chroma (`chromadb`), локальное хранилище на диске |
| Извлечение текста | `python-docx`, `openpyxl`, `pypdf` / `pdfplumber`, стандартный `csv` |

Зависимости фиксируются в `requirements.txt` с точными версиями.

### 7.2. Извлечение текста

| Формат | Способ | Единица структуры |
|---|---|---|
| md / txt | чтение UTF-8 | введение и разделы H2 |
| docx | `python-docx` | введение и разделы по заголовкам 2-го уровня, таблицы внутри раздела |
| pdf | `pypdf` / `pdfplumber` | введение и разделы, номер страницы сохраняется |
| csv | `csv` | строка таблицы, сериализованная как «столбец: значение», с заголовком |
| xlsx | `openpyxl` | строка листа, сериализованная с названиями столбцов; сохраняются лист и номер строки |

### 7.3. Эмбеддинги

- Модель: `intfloat/multilingual-e5-base`, размерность 768, векторы нормализованы (L2).
- Префиксы модели E5: для фрагментов документов `passage: `, для вопросов `query: `.
- Unicode NFC и нормализация пробелов применяются **только к тексту, который передаётся в модель эмбеддингов**. Текст фрагмента, который хранится в индексе и цитируется в ответе, сохраняется дословно, как в источнике.
- Вопрос: до 512 токенов, без усечения. Если вопрос длиннее, поиск возвращает ошибку и просит сократить вопрос.

### 7.4. Разбиение на фрагменты

- Разбиение структурное: введение документа (текст до первого H2) и каждый раздел H2 становятся отдельными фрагментами.
- Лимит фрагмента 384 токена токенизатора модели. В лимит входят префикс `passage: ` и название документа, которое добавляется к тексту фрагмента.
- Если раздел длиннее лимита, он делится по границам абзацев, а при необходимости по предложениям. Перекрытие между фрагментами 0.
- Таблицы: одна строка таблицы — один фрагмент с названиями столбцов.

### 7.5. Индекс Chroma

| Параметр | Значение |
|---|---|
| Хранилище | `.rag_store/` (persistent client) |
| Коллекция | `lumendesk-support` |
| Метрика | cosine (`hnsw:space = cosine`) |
| Векторы | вычисляются в Python и передаются явно; `embedding_function=None` |

Профиль поиска:

| Параметр | Значение | Назначение |
|---|---|---|
| `top_k` | 8 | число фрагментов, запрашиваемых из Chroma |
| `retrieval_threshold` | 0.20 | порог релевантности: фрагменты хуже порога в ответ не передаются; если таких не осталось, ответ «в базе нет сведений» |
| `authorization_probe_distance` | 0.35 | косинусное расстояние, при котором отсеянный политикой фрагмент считается ответом на вопрос; тогда помощник сообщает «недоступно для вашей роли», а не «нет сведений» |

Состав индекса:

- для каждого фрагмента: `chunk_id`, `doc_id`, `source_path`, `title`, `lang`, `is_translation`, `locator` (раздел / страница / лист+строка / номер строки CSV), `version`, `updated`, дословный текст;
- для индекса в целом (метаданные коллекции или файл манифеста в `.rag_store/`): идентификатор индекса, хеш корпуса (по `inventory.csv` и содержимому включённых файлов и переводов), хеш модели (название и ревизия), профиль разбиения и поиска.

### 7.6. Поиск и политика доступа

- Интерфейс: `python -m rag_demo ask --question "вопрос" --role support_agent --top-k 8 --output evidence/retrieval-{run}.json`. Команда печатает и сохраняет одинаковый JSON: hits с текстом, метаданными, расстоянием и происхождением (место в оригинале, отрывок оригинала для переводов). Ответ проверяется командой `finalize` (поля answer, citations, decision).
- Политика доступа (соответствие документов ролям, см. п. 2) хранится вне индекса (`access.csv`) и применяется при каждом запросе: список разрешённых `document_id` передаётся в `where` запроса Chroma, поэтому тексты закрытых документов не извлекаются.
- Отсеянные политикой фрагменты не выводятся. Используется только факт их близости (`authorization_probe_distance`), чтобы правильно выбрать формулировку отказа.

### 7.7. Когда нужна переиндексация

| Что изменилось | Действие |
|---|---|
| Корпус (`inventory.csv`, включённые файлы, переводы) | полная переиндексация |
| Модель эмбеддингов или её ревизия | полная переиндексация |
| Профиль (разбиение, `top_k`, пороги) | переиндексация |
| Политика доступа | только новый запрос; неизменный индекс не перестраивается |

Перед поиском `ask` сверяет хеши корпуса, модели и профиля с `.rag_store/manifest.json`. При расхождении поиск отказывает (stale) и предлагает выполнить `python -m rag_demo index`. Порог, роли и решения хранятся в `behavior/v2.json` (`policy show/use`) и не требуют переиндексации. В индекс попадают только документы со статусом `include`.

## 8. Правила ответа (модель чата)

1. Отвечать на русском языке.
2. Использовать только факты из найденных фрагментов. Если их недостаточно, сказать об этом.
3. После каждого утверждения или в конце ответа указывать источник в формате `[path, locator]` (оригинал).
4. Если ответ зависит от условий, которых нет в вопросе (тариф, часовой пояс / время UTC, регион, роль клиента в workspace), задать уточняющий вопрос или дать ответ по каждому варианту.
5. Если источники противоречат друг другу, показать оба, указать, какой документ новее или авторитетнее, и при неустранимом противоречии рекомендовать эскалацию.
6. Эскалация к человеку, если вопрос требует исключения из правил, касается юридических или персональных данных, злоупотреблений, компенсаций вне регламента или в документах прямо сказано, что решает руководитель.
7. Не раскрывать содержимое документов, недоступных роли, и исключённых документов.

Шаблон ответа: **Ответ → Условия / что уточнить → Источники → (Нужен человек: …)**.

## 10. Проверка работоспособности (приёмка)

Вопросы задаются через настоящий поиск (`python -m rag_demo ask`), ответы сверяются с документами, результаты и скриншоты сохраняются. Набор проверок должен покрыть следующие случаи:

| Сценарий | Что подтверждает |
|---|---|
| Факт из таблицы (csv/xlsx) | правильное чтение таблиц и ссылка на лист и строку |
| Факт из EN/FR документа | использование перевода и ссылка на оригинал |
| Вопрос по теме с дублями | в выдаче одна каноническая копия |
| Вопрос по теме со старой версией | ответ по актуальной версии, архив не используется |
| Противоречие источников | показаны оба, выбран действующий или предложена эскалация |
| Вопрос `support_agent` по материалу для руководителей | отказ без утечки содержания; тот же вопрос от `support_lead` получает ответ |
| Неполный вопрос (нет тарифа / времени) | уточняющий вопрос |
| Вопрос вне базы | честное «нет данных» |
| Ситуация для человека | явная эскалация |

Критерии приёмки:

- `inventory.csv` содержит ровно одну строку на каждый файл из `documents/`, у каждого решения заполнен `reason`, `id` у `include` уникальны.
- Исходные файлы не изменены (контрольные суммы до и после совпадают).
- Каждое фактическое утверждение в тестовых ответах подтверждено ссылкой, которую можно проверить в оригинале.
- Ни один тестовый ответ не опирается на исключённый или недоступный роли документ.
