## 2. Как устроена подготовка и что сохраняется

| Этап | Что сохраняется | Что повторяется при изменении |
|---|---|---|
| Сегментация | `corpus/segments/<путь>.json`: сегменты с текстом, sha и точным местом | только файлы, у которых изменился sha256 исходника или версия сегментатора (`_state.json`) |
| Перевод | `translations/<путь>.ru.txt`: блоки `@@ <sha12>` + русский текст | ключ перевода — хеш исходного абзаца или ячейки: переводить заново нужно только изменённые единицы, остальные подставляются как есть |
| Разбор срабатываний | `translations/_review.json`: решение и пояснение по каждой разобранной единице | разбирать нужно только новые срабатывания |
| Сборка | `corpus/prepared/<путь>.json` и `.ru.md`, `fragments.jsonl` | только документы, у которых изменился хотя бы один вход: сегменты, строка реестра, перевод, журнал разбора (`_state.json`) |

Проверка кэша: после изменения одного файла перевода сборка сообщила `rebuilt 1, cached 49`, сегментация — `segmented 0, cached 50`.

**Правило точных обозначений.** Не переводятся и проверяются на побайтное совпадение:
- названия тарифов Starter, Team, Enterprise и приоритеты P1–P4;
- коды регионов (EU-1, EU-2, US-1, CA-1), коды ошибок API, идентификаторы (INC-…, req-…, dead_letter, cartes.cree);
- технические параметры: UTC, SAML, ACS URL, MFA, HTTP 2xx, Retry-After, MiB, Europe/Paris;
- названия команд (Support Operations, Identity Platform, Finance…) и продуктов (Chrome, Slack, GitHub…).

Ячейки, целиком состоящие из таких обозначений, переводом не затрагиваются. Названия организаций-клиентов (Cedar Studio, North Paper…) оставлены как есть: это 28 единиц со значением `=`. Цитата клиента в №08 сохранена дословно, как этого требует сам документ.

## 4. Ошибки чтения и особенности извлечения

Ошибок чтения нет: все 50 файлов прочитаны, сегментация завершилась с 0 ошибок. Особенности, учтённые при извлечении:
- **md-файлы в CRLF.** Переводы строк приводятся к LF, текст не меняется.
- **PDF.** Абзацы собираются по межстрочному интервалу, номера страниц убираются. Абзац в №39 переходит со страницы 1 на страницу 2, поэтому у фрагмента `39-010` указано `page 1, page_end 2`.
- **xlsx.** Название листа (объединение A1:D2) и примечание (A3:D5) не теряются: к каждой строке таблицы привязан контекст листа с этими диапазонами.
- **txt без разметки.** Подзаголовки определяются по короткой строке без точки. Так найдено 7 подзаголовков в №24 и 4 в №37; подписи с датой и реплики клиентов («Клиент: «…»») подзаголовками не считаются.
- **№08.** Две реплики клиента, адресованные ассистенту, помещены в карантин (правило R9): `08-014` и `08-029`.

- Объём: 26 файлов, 861 единица перевода. Проза переводилась по абзацам (абзац docx, блок PDF, абзац md/txt), таблицы — по уникальным строкам: заголовки столбцов, значения, названия и примечания листов.
- Переведён весь деловой текст: разделы, подписи («From Billing Operations…»), заголовки таблиц и листов, примечания листов, условия и реплики в письмах. Пересказов и добавлений нет. Соотношение длины перевода и оригинала проверялось для каждого абзаца длиннее 60 символов: допустимый коридор 0,75–1,8, вне его оказалось одно короткое предложение (0,74), оно разобрано вручную.

- Записи таблиц собираются из переведённых ячеек. Каждая запись хранит пары «заголовок — значение» на обоих языках и ссылку на ячейку, например: `Case: Enterprise P1; Target: 15; Unit: minutes` → `Случай: Enterprise P1; Цель: 15; Единица: минуты` (лист «Targets», A8:D8; ячейки A8, B8, C8, D8).

## 6. Проверка точности: как сверялись переводы

Для каждой пары «оригинал — перевод» скрипт `check_translation.py` проверяет:

1. **Числа.** Мультимножества чисел оригинала и перевода должны совпасть. Учитываются и числа, записанные словами: `fifteen`, `forty-eight`, `three-failure`, `sept`, `cent quatre-vingts`, `пятнадцати`, `сорока восьми`, `оба`.
2. **Точные обозначения.** Каждое обозначение из оригинала должно присутствовать в переводе без изменений. Нарушений не найдено.
3. **Отрицания.** Если в оригинале есть not / no / never / ne … pas / jamais / sans, в переводе должно быть не / нет / никогда / без, и наоборот. Обороты «не менее / не более / не позднее» отрицанием не считаются.
4. **Условия и ограничения.** only / seulement → только; at least / au moins → не менее; at most / up to / au plus tard → не более / не позднее; within / dans les → в течение; must / doit → должен / нужно; immediately → немедленно; before / avant → до / прежде; after / après → после / через.
5. **Роли и доступ.** Support lead → руководитель поддержки, administrator → администратор, owner / propriétaire → владелец / billing owner.
6. **Длина.** Перевод не должен быть заметно короче или длиннее оригинала: защита от пересказа и дописывания.

### Итог сверки

- **Автоматически проверено:** 793 пары. Ещё 28 единиц оставлены как в оригинале: это имена собственные.
- **После уточнения правил сработало 33 проверки:** отрицания 15, условия 15, числа 2, длина 1. Каждое срабатывание разобрано вручную, решение с пояснением записано в [translations/_review.json](translations/_review.json):
  - **30 срабатываний — допустимые соответствия.** Например, «until X» → «пока не X», «incomplete» → «неполные», «before tax» → «без налога». Французское «ne … que» в «ne signifie pas que» вообще не означает «только».
  - **3 ошибки исправлены**, см. примеры выше.
- **Первичный прогон до уточнения правил дал 80 срабатываний.** Ложные шли от оборотов «не менее / не более / не позднее», от слова «оба» (= 2) и от «after» внутри «Retry-After». Правила уточнены, ни одно срабатывание не отключено без разбора.
- **Ограничения доступа в переводах сохранены.** «Only the workspace owner or an administrator» → «только владелец workspace или администратор» (№32). «Escalate … to support lead» → «руководителю поддержки» (№26). Пометки «Только руководителям поддержки» есть только в русских документах №12, №44, №45 и там не менялись.

## 7. Решения о включении, доступе, версиях и повторах

Правила отбора R1–R12 записаны в [registry/decisions.json](registry/decisions.json) и в [corpus-passport.md](corpus-passport.md). Актуальность определялась по тексту: владелец, дата вступления или сверки, пометки о замене, черновике или гипотезе. Имя файла («новый», «final», «копия») и дата изменения файла как основание не использовались. Например:
- №22 «Тарифы новый» включён, потому что в тексте сказано «подтверждены с 1 сентября»;
- №19 «Team Flex — новый вариант» исключён, потому что в тексте сказано «не образуют действующие условия»;
- №25 и №30 с пометкой «копия» включены: других экземпляров этих документов в корпусе нет.

**Повторы после перевода.**
- **Точные совпадения между документами.** Найдено 23 группы, все внутри пар 13/37 и 31/39. В каждой группе один основной фрагмент; копии исключены из поиска, но их места сохранены в `also_in`. Поэтому одинаковые сведения не считаются независимыми подтверждениями.
- **Частичные совпадения.** Найдено 10 пар с совпадением ≥ 0,6 по словам: 9 пар между №10 и №43 и пара №49 ↔ №50. Они связаны полем `similar_to`, но ничего не удалено. В паре `10-010` ↔ `43-010` различается именно ставка кредита, а №49 содержит исключение P1 Enterprise на 14 июля, которого нет в №50.
- **Другие частичные пересечения.** №28 ↔ №32 и №33 ↔ №35 описывают одни правила разными словами, порог совпадения они не проходят. Эта связь записана в реестре в поле `related`; оба документа каждой пары включены, потому что в каждом есть собственные условия.

## 8. Метаданные фрагмента для поиска

Каждая строка [corpus/prepared/fragments.jsonl](corpus/prepared/fragments.jsonl) содержит поля:

| Группа полей | Поля |
|---|---|
| Идентификация | `fragment_id`, `doc_no`, `doc_id`, `doc_version`, `kind` |
| Оригинал | `source_path`, `source_sha256`, `source_lang`, `format`, `text_orig` (для EN/FR), `segment_sha` |
| Точное место | `locator`: строки для md/txt, абзац w:p для docx, `page`, `page_end` и `block` для pdf, лист, строка и диапазон для xlsx, `csv_row` для csv; `locator_text`; для таблиц ещё `cells` (ссылка на ячейку, заголовок и значение на обоих языках) и `context` (лист, название и примечание с диапазонами объединённых ячеек) |
| Текст | `text_ru`, `section`, `section_ru`, `translation` (original_ru / translated / kept_as_is), `translation_review` |
| Обращение | `status`, `index`, `access`, `trust`, `quarantine`, `dup_group`, `duplicate_of`, `also_in`, `similar_to`, `conflict_group`, `handling` |

Пример: фрагмент `49-008` из `documents/Франция/Rappels et jours fériés.pdf`, стр. 1, блок 8, язык оригинала fr. Текст: «Для этого исключения P1 Enterprise обратный звонок выполняется не позднее чем через 45 минут…». Поле `handling`: «Действующий материал. Перевод с FR; цитировать оригинал по указанному месту.»

Для каждого документа есть читаемая русская версия `corpus/prepared/<путь>.ru.md`: перед каждым фрагментом стоит комментарий с его id, местом в оригинале и статусом.

## 9. Что остаётся открытым

1. **Ставка кредита Team P1** (№10 или №43) по документам не устанавливается. Помощник должен показывать оба источника.
2. **Оригинал пары 13/37** не установлен. Основным выбран русский №13, потому что для него не нужен перевод и он лежит в тематической папке.
3. **Метаданные из постановки** (`permission`, `sensitivity`, `inclusion_status`) в документах отсутствуют. Решения приняты по правилам R1–R12, выведенным из текста документов. Если появятся настоящие значения этих полей, их нужно будет внести в `decisions.json` и пересобрать корпус (`prepare.py` пересоберёт только затронутые документы).
4. **Индекс Chroma ещё не строился.** Нарезка фрагментов под лимит 384 токена с добавлением контекста раздела и листа — следующий шаг по [spec.md](spec.md).
