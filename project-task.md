# project-task.md - Постановка задачи на разработку RAG-системы LumenDesk

LumenDesk — вымышленная платформа для совместной работы. 

Нужно создать ИИ-помощника, который будет отвечать на русском языке, находить правила продукта в документах и показывать, откуда взялись сведения.

Python находит фрагменты документов. Модель текущего чата ИИ отвечает по этим фрагментам и указывает источники.

## Ролевая модель

ИИ-помощником пользуются сотрудники LumenDesk с разными уровнями доступа к информации из документов в зависимости от их роли:

support_agent - специалист поддержки
support_lead - руководитель группы поддежки

## Круг вопросов, на которые отвечает ИИ-помощник

ИИ-помощник отвечает на вопросы:
- о тарифах,
- о рабочих пространствах,
- о файлах,
- о восстановлении,
- о поддержке,
- об API,
- о настройках доступа.

Источником фактов принимает разрешенные действующие материалы компании.

## Документы базы знаний

Документы компании могут быть на русском, английском и французском языках. Документы на английском и французском продублированы переводом на русский с сохранением ссылки на оригиналы.

Все исходники лежат в `docs/`. Метаданные в начале файла содержат `id`, `title`, `owner`, `version`, `updated`, `permission`, `sensitivity` и `inclusion_status`.

`inventory.csv`: одна строка на каждый исходный файл, столбцы `path,id,title,owner,version,updated,status,reason`. Значения брать из документов. В `status` записать `include` или `exclude`, в `reason` — основание решения.

Включать только актуальные документы с `permission: allowed`, `sensitivity: synthetic` и `inclusion_status: approved`. Из полных дубликатов оставлять одну копию и объяснять выбор. При наличии новой версии исключать старую. Не удалять и не переписывать исходники. У включённых документов должны быть уникальные `id`; исключённая копия может иметь тот же `id`.

В `corpus-passport.md` кратко записать назначение базы, состав включённых файлов и причины исключений. Список разрешённых документов определяется строками `include` в инвентаре.
